# What's changed

- Added the continuity-v2 foundation so durable personal continuity is no longer faked through
  thread metadata or runtime-presence signals. The repo now ships typed continuity records for the
  assistant profile, confirmed continuity items, and continuity evidence.
- Rewired prompt assembly so default continuity comes from the assistant profile plus retrieved
  typed continuity, while legacy `life-state` and `recent-reflection` blocks are dropped by
  default behind a compatibility flag instead of being treated as universal continuity.
- Removed the legacy thread-scoped relationship subsystem instead of carrying it forward under a
  softer name. This deletes the prompt block, Settings observability surface, IPC bridge, runtime
  persistence hooks, and the unused `brain/thread-context.md` note path so the shipped product no
  longer implies a social model it does not actually own.
- Added conservative explicit-statement capture on persisted user messages (`my name is ...`,
  `call me ...`, `i prefer ...`, `please remember ...`, plus initial Chinese counterparts), with
  incognito exclusion and evidence writeback.
- Removed speculative continuity-only `projects` / `project_threads` / `open_loops` schema pieces,
  the old identity-context prompt builder, and the dead thread-relationship table path before
  release, so the shipped surface matches the actual product path instead of carrying duplicate
  task state or dead prompt APIs.
- Updated tests and docs to match the new semantics, including dedicated continuity-service
  coverage, context-assembler integration checks, module docs, a continuity-v2 design note, and
  postmortems documenting both the earlier semantic overclaim and the deeper subsystem-scaffolding
  mistake behind it.
