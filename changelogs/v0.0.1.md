# What's changed

- Added the first deterministic life-runtime kernel for iKi: persistent `life_state` /
  `life_episodes` storage, a shared background tick, proactive-task lifecycle ingress,
  `life-state` chat-context injection, sparse hourly `life_reflections` with conservative
  single-thread memory write-back, semantic-day recap / next-day planning from hourly recaps +
  todo/proactive commitment surfaces, explicit owner mode controls (`sleep`, `focus`, `stay
  available`) with deferred-while-task-running semantics, first-class thread-scoped
  `relationship_states` with owner-baseline projection, message-driven interaction timestamps,
  dedicated relationship prompt injection, and a new Settings -> Life observability section so
  iKi's current presence/activity/social frame is grounded in structured state instead of
  per-thread roleplay.
- Hardened local execution boundaries: file tools now validate against real filesystem paths
  instead of lexical path segments (blocking symlink escapes), the embedded daemon now defaults
  to loopback (`127.0.0.1`), daemon bootstrap registration tokens now use strong randomness and
  rotate after successful client registration, and network proxy overrides now restore prior
  process proxy environment values when app-managed proxying is disabled.
- Refactored renderer tool cards into a dedicated `ChatToolPart` component and tightened the chat
  composer's renderer-side Electron API typing to remove key `any` casts from the main chat path.
- Added first-class desktop theme preset support with a shared theme registry, separate
  `themePresetId` configuration, renderer `--theme-*` input slots, Base46 compilation for custom
  presets, startup window background resolution from the active preset, and a dedicated
  `Settings -> Color Scheme` workflow with searchable built-in galleries, quick-start theme seeds,
  live preview, and guided simple/advanced custom theme editing.
- Added first-class persistent ToDoList support with SQLite-backed `todo_lists` / `todo_items`
  storage, dedicated built-in todo tools (`list/read/write/delete`), chat auto-tool integration
  for checklist workflows, approval gating for state changes, and a design note covering the new
  architecture.
- Upgraded proactive task execution from an implicit nullable-tools convention to an explicit
  agentic tool strategy model (`auto`, `manual`, `disabled`), added a dedicated scheduled-task
  execution prompt with previous-run context, and exposed the strategy in Settings so recurring
  tasks can autonomously aggregate fresh web information without losing safe control boundaries.
- Added a unified chat context assembler with rolling thread summaries, bounded recent-history /
  memory / skill budgets, scoped same-client memory retrieval, and first-class context reports in
  the chat UI.
- Consolidated `chat_context` so memory-present and memory-absent turns now share one bounded
  `summary -> memory -> affect -> skills -> report` assembly path instead of maintaining duplicate
  tail branches.
- Reworked context usage presentation in the chat UI: the old expandable `context` reference entry
  was removed, and the composer now shows a compact gauge-style context usage badge with hover
  details.
- Hardened `chat_thread_context` storage so bridge/daemon chat paths do not fail when running
  against an older SQLite file that has not yet applied the new context-summary migration; the
  schema is now lazily ensured at access time as a compatibility backstop.
- Added a design note and postmortem for the context engineering pipeline.
- Polished the chat chrome to match the lighter reference treatment: the composer now uses
  theme-aware surface tokens instead of a hard-coded dark gradient, and outgoing user messages use
  softer rounded bubble styling with dedicated light/dark palette control.
- Fixed composer toolbar control visibility in light mode by giving icon buttons, including speech
  input, explicit themed surfaces and a less aggressive disabled treatment.
- Unified the chat `ToolSelector` visual design with `SkillSelector`, including shared panel,
  actions, flat list rows, and checkbox treatment; removed the legacy default "manual + select all
  built-in tools" behavior so the selector now opens in `auto` like skills.
- Added first-class assistant citations for tools, skills, and memory retrieval:
  streaming now preserves `skill-usage` parts, the chat view shows a compact reference summary, and
  memory matches were redesigned from the old dashed card into cleaner citation panels.
- Fixed skills preview metadata extraction to read the YAML frontmatter `description`
  from `SKILL.md`, with markdown-body fallback for legacy skills.
- Added an enforceable CI quality gate workflow (`quality-gate`) that runs
  `eslint --ext .ts,.tsx .`, `tsc`, and tests with coverage on PRs and `main`.
- Added executable coverage policy with `@vitest/coverage-v8`,
  `npm run test:coverage`, and global baseline Vitest thresholds.
- Expanded frontend quality checks with `.vue`-aware linting, `vue-tsc`,
  a renderer-focused `npm run test:renderer` path, and first behavioral
  component tests for `ToolSelector` and `ProvidersSettings`.
- Expanded the executable coverage gate to include Vue single-file components
  (`src/**/*.vue`) with a realistic first ratchet, so renderer logic now
  counts toward CI coverage instead of living outside the enforced floor.
- Added renderer behavior tests for `ChatInput` and `ChatToolPart`, shifting
  coverage toward real interaction logic (model selection, send flow, tool
  approval/collapse/reference rendering) instead of brittle source-text checks.
- Added behavior coverage for `McpSettings` and `SettingsTasksSection`,
  including config toggles, MCP server form normalization/validation, task
  provider-model linkage, manual-tool validation, and existing task updates.
- Added interaction coverage for `SettingsSpeechSection`, including provider
  switching, whisper model selection, download progress handling, and automatic
  model application after download.
- Added interaction coverage for `SettingsMemorySection`, including retrieval /
  emotion config updates, memory viewer thread hydration, all-thread search
  behavior, and long-memory create/edit/delete flows with search refresh.
- Added high-value regression tests for chat orchestration and renderer stream
  control:
  - `tests/main/services/chat/chat_streaming.test.ts`
  - `tests/renderer/ui_stream_controller.test.ts`
- Fixed Vitest 4 constructor-mock compatibility in core runner/runtime tests.
- Added commit governance automation: `commitlint` rules, Husky `commit-msg`
  enforcement, and `commitizen` (`cz-git`) interactive commit flow.
- Added end-to-end token usage analytics: persisted `chat_usage_events` telemetry,
  `chat:usage:summary` IPC/preload API, and a new Settings -> Usage dashboard with
  period filters, yearly activity heatmap, and monthly cost trend cards.
- Started migrating settings dropdowns onto a shared app-owned `SettingsSelect`: the Usage period
  filter plus the General settings selectors (including grouped Tool Model choices) now keep their
  expanded menus inside the renderer theme instead of falling back to OS-native popup styling.
- Promoted more renderer surface treatment into the theme layer so Base46 presets now influence
  shared elevation/highlight tokens too; multiple hard-coded status, tooltip, icon-placeholder,
  and user-bubble inline colors were moved onto semantic theme tokens or token-derived mixes.
- Unified the Settings -> Life right-hand content pane with the rest of Settings by moving it onto
  the shared settings card/status primitives and canonical theme tokens, eliminating its one-off
  surface treatment.
- Added CI guardrails for semantic PR titles and PR commit linting, alongside
  explicit PR-process expectations for architecture-impacting docs/changelog
  updates.
- Standardized manual release flow: version intent remains manual, curated
  product notes live in `changelogs/`, and no machine-generated root
  `CHANGELOG.md` is required.
- Added `release-build` workflow to automatically run `npm run make` after
  explicit `package.json` version bumps on `main` and published GitHub
  releases, then upload build artifacts.
- Hardened `release-build` with a lockfile preflight (`npm ci --ignore-scripts`)
  and a dedicated release publish job so release asset upload is single-writer
  instead of matrix-parallel.
- Added design and postmortem documentation describing the commit governance gap
  and long-term control strategy.
- Fixed duplicate assistant text rendering when identical content was emitted before and after
  tool execution in the same streamed turn; renderer now deduplicates tool-bridged repeated text
  segments during finalization.
- Fixed frameless window white-edge halo by removing the renderer root's legacy 40px corner radius,
  enforcing full-bleed root background colors, and setting explicit dark Electron `backgroundColor`
  defaults for both main and settings windows.
- Further reduced macOS shell halo by disabling native vibrancy and window shadow on main/settings
  windows so edge rendering remains fully theme-controlled.
- Refined light-theme frameless window chrome with an explicit app-shell border and renderer-driven
  native shadow opt-in, so iKi stays visually separated when overlapping other applications without
  reintroducing dark-theme halo artifacts.
- Tightened the light-theme chat composer edge treatment by disabling backdrop blur there and
  replacing the hazy bottom-corner shadow with a crisper tokenized surface shadow.
- Unified outgoing user bubble corner radii across light and dark themes, including builtin and
  Base46-derived presets, so chat bubble border shape stays consistent between theme variants.
- Aligned sidebar bottom spacing with chat composer spacing by binding both to
  `--chat-composer-padding`, removing the visible bottom-gap mismatch.
- Fixed renderer layout sizing so chat and settings pages size against the app shell's available
  area instead of raw viewport height, preventing content from appearing clipped when frameless
  window insets or inner shell spacing are tightened.
- Fixed narrow-window chat overflow with the sidebar open by allowing the main chat column and tool
  cards to shrink horizontally, and by making tool card metadata wrap instead of forcing cards past
  the visible content area.
- Unified main/settings window DevTools auto-open policy: auto-open is now disabled by default, can be explicitly enabled in development via `IKI_AUTO_OPEN_DEVTOOLS=true`, and is forced off in packaged builds to avoid noisy internal CDP Autofill warnings.
- Fixed proactive task creation/update IPC payload serialization in preload so Vue reactive proxies (for example task tool arrays) no longer fail with "An object could not be cloned."
- Further hardened proactive task IPC against Electron structured-clone failures by normalizing the
  settings task form to raw plain data before submission, serializing task IPC responses in the main
  process as well, and adding regression tests around real Vue reactive payloads.
- Fixed proactive tasks targeting NapCat-owned threads so successful runs now attempt real QQ
  delivery through the active reverse WebSocket bridge, and bridge disconnects, timeouts, or
  OneBot send failures are surfaced as explicit task errors instead of silent local-only success.
- Refactored ChatInput speech handling into a composable and extracted UI message conversion helpers.
- Added speech service regression tests covering provider routing, OpenAI transcription calls,
  and failure handling.
- Added a design note and postmortem for the chat input refactor.
- Added workflow self-optimization with auto tool routing and auto-pinned skills per thread.
- Added workflow profiles storage, settings toggle/reset, and a design note for the optimization loop.
- Integrated emotion context into the agent decision loop with configurable affect aggregation.
- Added emotion event storage, tests, and documentation for the new emotion pipeline.
- Added optional real-time emotion analysis for current responses (configurable).
- Persisted per-thread affect state and surfaced it in the Memory viewer.
- Added affect-based tool guardrails with configurable thresholds.
- Split emotion analysis into a task-style `EmotionAgent` and pluggable `EmotionRuntime`,
  preserving existing call sites while preparing for external emotion model backends.
- Split title generation and catalog selection into task-style agents and pluggable runtimes,
  while preserving existing compatibility wrappers.
- Introduced a chat-facing `ConversationRunner` contract and the `SimpleConversationRunner`
  layer so chat streaming/approval flows no longer depend directly on `SimpleAgent`.
- Reimplemented `SimpleConversationRunner` directly on shared AI SDK helpers and `ToolRegistry`,
  removing the remaining production-path dependency on `SimpleAgent` while preserving in-memory
  approval continuation semantics.
- Converted `ConversationRunner` to request-style `history + prompt` calls, removing the
  chat-side runner preload step and passing reconstructed history explicitly during approval
  recovery.
- Extracted a shared `prepareChatTurn(...)` planner in chat orchestration so `send()` and
  `stream()` now share message normalization, affect/context assembly, tool resolution, guard
  policy, runtime-hint persistence, and `history/prompt` splitting.
- Split the old monolithic `chat_ui.ts` helper into focused message-conversion, persistence, and
  stream-emission modules while preserving the existing barrel exports for callers.
- Introduced a single-step `PromptTextGenerator` seam so task runtimes and memory summarization
  no longer type directly against `SimpleAgent`.
- Reimplemented `SimplePromptTextGenerator` directly on AI SDK and shared runtime helpers, so
  task runtimes no longer execute through `SimpleAgent` indirectly.
- Moved chat/runtime message handling onto `ModelMessage[]` so chat streaming/approval paths now
  pass AI SDK message history directly into `ConversationRunner`.
- Consolidated shared config/tool/prompt/history assembly in `src/core/agent/ai_sdk_runtime.ts`
  and reused it across the direct runner/generator path.
- Removed the remaining `SimpleAgent` / `BaseAgent` / `createAgent` / `AgentMessage`-style legacy
  surface from `src/core/agent`, leaving only the current runner-first runtime API.
- Added structured `chat_tool_approval_sessions` / `chat_tool_approvals` persistence so approval
  recovery no longer scans serialized chat messages or depends on mutable thread config snapshots.
- Added UI CRUD for long-term memory entries with IPC update/delete hooks and manual creation.
- Added unit tests covering proactive task IPC, scheduling runs, and database updates.
- Added cron-based scheduling for proactive tasks with UI support and persistence.
- Fixed migration index to include 010_add_proactive_tasks_cron.
- Added an MCP support design plan covering architecture, data model, UI, and security.
- Implemented MCP server persistence, manager lifecycle, and dynamic tool registration.
- Added MCP IPC + daemon endpoints and a Settings UI for configuring servers and policies.
- Added per-conversation MCP server toggles in ToolSelector, persisted thread selection state,
  and MCP auto-tool routing for explicitly enabled servers.
- Aligned MCP transports with AI SDK guidance: Streamable HTTP is the preferred remote default,
  SSE remains available for legacy servers, and remote MCP requests now reject redirects.
- Propagated MCP `outputSchema` into AI SDK tool definitions and normalize typed MCP tool results
  before returning them to the model runtime.
- Added MCP unit tests covering typed output normalization, secure transport construction, and IPC forwarding.
- Expanded high-risk regression coverage for scheduler/time math (`task_schedule`), network timeout/retry/proxy handling (`core/network/http`), Fetch tool parsing/error handling, and full MCP IPC handler forwarding.
- Fixed test-time native module ABI warning by isolating `chat_memory_emotion_cache` from real `affect_state` DB access (mocked in unit test).
- Added per-module documentation under docs/modules.
- Fixed UI message normalization to convert legacy tool parts and prevent empty-part validation errors that broke tool calling.
- Added MCP server labels to expanded tool call/result cards in ChatView.
- Added optional `description` support to all built-in tool input schemas so
  tool call cards can consistently display a short call reason (for example
  "Check current playback status") when the model provides it.
- Replaced the chat auto-tool built-in hard-coded allowlist with per-tool `autoAllowed`
  metadata, then flipped the default so built-in tools and enabled-server MCP tools are auto-routable
  unless they explicitly opt out, while still passing approval/source metadata into the tool router
  so it can choose broad toolsets without becoming indiscriminate.
- Fixed daemon chat parity for MCP server selection: `/v1/chat/send` and WS `start` now accept
  `mcpServerIds` (and `mcp_server_ids`) and enforce client allowlist gating (`mcp:*`,
  `mcp:server:<id>`, or mapped MCP tool names).
- Added desktop-managed daemon auto-start on app launch (with `IKI_DAEMON_AUTOSTART=false` opt-out)
  and introduced `--iki-daemon` runtime mode for daemon-only startup flows.
- Added daemon listen host/port settings in `Settings -> Bridges -> NapCat (QQ)`, and apply updates
  by restarting the desktop-managed daemon.
- Switched desktop-managed daemon startup to embedded mode in Electron main process by default,
  avoiding a second Electron process while keeping daemon health checks and restart behavior.
- Added explicit NapCat reverse WebSocket connection lifecycle logs (upgrade, connected,
  disconnected, auth/disabled rejection) for faster bridge troubleshooting.
- Updated Sidebar thread visibility to hide non-desktop bridge conversations (for example
  `NapCat/QQ` threads) from the main desktop chat list.
- Hardened Electron renderer window loading in development: the main/settings windows now wait for
  the Vite dev server, fall back to built renderer HTML when available, and otherwise show an
  explicit local recovery page instead of surfacing raw `ERR_CONNECTION_REFUSED` load failures.
- Added a design note clarifying that IM integration is a primary access layer for iKi's
  shared brain, while desktop remains the control plane and iKi does not pivot into a
  generic bot-platform product model.
