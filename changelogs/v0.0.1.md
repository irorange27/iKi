# What's changed

- Emotion analysis now ships enabled by default. Real-time same-turn analysis remains opt-in, so the
  default posture enables asynchronous affect accumulation without automatically adding an extra
  model call to every reply.
- Promoted affect from prompt-sidecar metadata to a first-class runtime signal: chat-turn
  preparation now carries structured affect state into skill/tool routing, persists it into thread
  runtime metadata, emits explicit `affect-signal` UI references, and broadens the response-side
  prompt contract from tone-only guidance to a wider but still bounded decision signal for
  clarification depth and action autonomy.
- Hardened the agent runtime configuration boundary so explicit `ConversationRunner` /
  `PromptTextGenerator` configs no longer re-enter app-config / SQLite loading behind the scenes,
  eliminating a false-green test path where runtime construction could log native DB-load failures
  yet still pass by silently falling back to defaults; added regression coverage that explicitly
  fails if runner/generator tests start touching global app config again.
- Added a shared strict error-log test harness: Vitest now fails on unexpected `console.error`
  output by default, and suites that intentionally exercise error-reporting paths must explicitly
  declare the expected log entries. Existing IPC / provider-verification tests were migrated onto
  that harness so real runtime errors no longer disappear behind silent `console.error` spies.
- Normalized the SQLite migration sequence after the duplicate `009_*` split: canonical migration
  files now run in a unique `001..021` order, the migration runner recognizes and rewrites legacy
  executed names onto the new canonical identifiers, and new tests now fail if migration files or
  registration drift out of a contiguous one-number-per-step sequence again.
- Introduced a shared renderer/preload `ElectronApi` contract, wired preload exposure through that
  single typed surface, removed repeated renderer-side `window: any` escape hatches across key
  settings/chat entrypoints, continued migrating remaining app-shell/chat helper bridge fragments
  onto that shared contract, fixed daemon registration so the first non-bridge client still claims
  legacy threads after the internal NapCat client is ensured, and expanded executable boundary
  coverage across chat IPC, remaining CRUD/system IPC modules, and daemon
  registration/auth/send paths.
- Reassessed the first renderer/preload remediation wave and documented the new priority order:
  preload boundary drift is now largely closed (`npm run -s ci:quality` green with `107` test
  files / `406` tests; preload line coverage above `98%`), while the next debt paydown should
  focus on orchestration-heavy coverage gaps, settings state ownership normalization, chat transport
  assembly cleanup, and decomposition of oversized renderer/daemon files.
- Added characterization coverage for the next orchestration hotspots: `useChatStreaming` now has
  explicit tests for stream-stop/thread-switch, edit-and-truncate resend, and first-send thread
  creation; `ChatView` now has renderer wiring tests around approval, edit/cancel draft replay, and
  composer context-usage propagation; and daemon coverage now includes CORS preflight plus enforced
  authenticated ownership on thread creation.
- Added renderer coverage for two previously soft edges: `Sidebar` now has behavior tests for
  desktop-thread filtering, confirmed deletion, and settings entry wiring, while `useAppConfig`
  now has integration tests for initial config hydration, live config-update subscription,
  debounced autosave coalescing, and `saveNow()` flushing of pending writes.
- Added explicit lifecycle and service-boundary coverage in the renderer shell: `useChatViewLifecycle`
  now has tests for one-time initialization, listener registration/cleanup, UI-chunk forwarding,
  task-push forwarding, and compatibility with older builds lacking task listeners; `config_service`
  now has direct tests for Electron bridge delegation, default daemon-log limits, missing-bridge
  errors, and noop update-subscription fallback behavior.
- Added focused coverage for renderer tool metadata behavior: `useToolMetadata` now has direct tests
  for source-map hydration from the shared tool list, lazy MCP label loading on first lookup, and
  warning-path behavior when skill-reference opening fails or the bridge throws.
- Added renderer interaction/lifecycle coverage for two more shell seams: `useMarkdownCopy` now has
  direct tests for clipboard copy, `execCommand` fallback, and non-copy click guards, while
  `useConfigEffects` now has lifecycle tests for modern and legacy media-query listener wiring,
  system-theme reapplication, and cleanup on unmount in addition to the existing CSS-token tests.
- Added the first deterministic life-runtime kernel for iKi: persistent `life_state` /
  `life_episodes` storage, a shared background tick, proactive-task lifecycle ingress,
  `life-state` chat-context injection, sparse hourly `life_reflections` with conservative
  single-thread memory write-back, semantic-day recap / next-day planning from hourly recaps +
  todo/proactive commitment surfaces, explicit owner mode controls (`sleep`, `focus`, `stay
available`) with deferred-while-task-running semantics, first-class thread-scoped
  `relationship_states` with owner-baseline projection, message-driven interaction timestamps,
  dedicated relationship prompt injection, and a new Settings -> Life observability section so
  iKi's current presence/activity/social frame is grounded in structured state instead of
  per-thread roleplay.
- Hardened local execution boundaries: file tools now validate against real filesystem paths
  instead of lexical path segments (blocking symlink escapes), the embedded daemon now defaults
  to loopback (`127.0.0.1`), daemon bootstrap registration tokens now use strong randomness and
  rotate after successful client registration, and network proxy overrides now restore prior
  process proxy environment values when app-managed proxying is disabled.
- Aligned local desktop release scripts with the Electron Forge release path: `app:dev` now
  routes through Forge start, `app:preview` launches the latest packaged desktop build for manual
  inspection, `app:build` delegates to Forge `make`, and the public README now documents the
  actual install / dev / release flow instead of placeholder setup text.
- Hardened packaged desktop verification: Forge now carries the main-process runtime externals
  (including native modules) into the app bundle instead of relying on the repository
  `node_modules`, and native `.node` files are auto-unpacked for asar compatibility.
- Tightened packaged speech/runtime assets so the app bundle now ships only the required
  `whisper-node`/`ffmpeg-static` executables plus `better-sqlite3` native binary, while downloaded
  Whisper models live under user data instead of inflating `app.asar`.
- Refactored renderer tool cards into a dedicated `ChatToolPart` component and tightened the chat
  composer's renderer-side Electron API typing to remove key `any` casts from the main chat path.
- Added first-class desktop theme preset support with a shared theme registry, separate
  `themePresetId` configuration, renderer `--theme-*` input slots, Base46 compilation for custom
  presets, startup window background resolution from the active preset, and a dedicated
  `Settings -> Color Scheme` workflow with searchable built-in galleries, quick-start theme seeds,
  live preview, and guided simple/advanced custom theme editing.
- Added first-class persistent ToDoList support with SQLite-backed `todo_lists` / `todo_items`
  storage, dedicated built-in todo tools (`list/read/write/delete`), chat auto-tool integration
  for checklist workflows, approval gating for state changes, and a design note covering the new
  architecture.
- Upgraded proactive task execution from an implicit nullable-tools convention to an explicit
  agentic tool strategy model (`auto`, `manual`, `disabled`), added a dedicated scheduled-task
  execution prompt with previous-run context, and exposed the strategy in Settings so recurring
  tasks can autonomously aggregate fresh web information without losing safe control boundaries.
- Added a unified chat context assembler with rolling thread summaries, bounded recent-history /
  memory / skill budgets, scoped same-client memory retrieval, and first-class context reports in
  the chat UI.
- Consolidated `chat_context` so memory-present and memory-absent turns now share one bounded
  `summary -> memory -> affect -> skills -> report` assembly path instead of maintaining duplicate
  tail branches.
- Reworked context usage presentation in the chat UI: the old expandable `context` reference entry

- Hardened `chat_thread_context` storage so bridge/daemon chat paths do not fail when running

- Added a design note and postmortem for the context engineering pipeline.

- Removed two remaining chat-composer races: per-thread tool selection now resets cleanly when the
