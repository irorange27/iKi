# What's changed

- Fixed a daemon ownership regression that could make the desktop sidebar appear to "lose" prior
  conversations after the first external client registration. The daemon no longer reassigns
  legacy desktop threads to the first registered app client, and a startup migration now restores
  pre-registration threads that were wrongly claimed by that first client back to desktop/null
  ownership while keeping genuinely newer external threads client-owned.
- Fixed the assistant reference-summary tool badge so it no longer conflates tool-call counts with
  tool types. The inline badge now explicitly reports tool invocations, while the hover detail
  separately shows how many distinct tools were used plus a per-tool call breakdown.
- Raised the desktop chat tool-loop default from `5` to `10` iterations and carried the effective
  per-turn `maxIterations` value through approval-session persistence/recovery, so approval-gated
  turns no longer silently resume under a smaller loop ceiling than the one they started with.
- Added bounded parallel execution to the external daemon benchmark harness: `npm run benchmark:daemon`
  now accepts `--parallel N` while keeping the default single-threaded behavior, preserves stable
  task-result ordering in exported artifacts even when progress logs complete out of order, and
  downgrades per-task thread-creation failures into isolated task errors instead of aborting the
  entire benchmark run.
- Fixed tool-stream final-answer retention for daemon-driven benchmark runs and other chat clients:
  if a provider completes a tool-using turn with only a final assembled response instead of
  incremental `text-delta` chunks, iKi now preserves that answer through the tool loop, exposes it
  on the daemon stream result payload, and lets the benchmark harness score from that final text
  instead of recording a false empty prediction.
- Hardened optional `models.dev` capability lookups so network timeouts no longer impose a hidden
  per-turn latency tax during chat and benchmark runs: remote model-metadata fetch failures now
  enter a cooldown window, reuse any previously cached catalog when available, and degrade to local
  provider metadata without re-logging or re-blocking every subsequent turn.
- Added an explicit tool-iteration override for daemon-driven chat/benchmark calls, so external
  evaluation harnesses can raise the tool-loop ceiling above the then-current desktop product
  default of `5` when browse-heavy tasks need extra search/fetch rounds before producing a final
  answer.
- Added a first-class built-in `edit` file tool that applies ordered exact-text replacements to an
  existing file instead of forcing the model to rewrite the whole file for small changes. The tool
  is approval-gated like other write-capable filesystem actions, rejects ambiguous multi-match
  edits unless `replaceAll` is explicit, is wired through daemon client allowlists and renderer
  tool cards, and comes with schema / payload / workspace-boundary tests so patch-style edits are
  now a stable part of the standard iKi tool surface.
- Refined user-message hover controls to match the chat-bubble reference affordance: hovering a
  user bubble now reveals `copy`, `regenerate`, `edit`, and `more` from left to right beneath the
  bubble's trailing edge, `copy` uses the same clipboard fallback path as code-block copy, and
  `regenerate` now reuses the existing edit-and-resend thread truncation flow through a dedicated
  programmatic composer send hook instead of introducing a second resend path.
- Hardened the skill-metadata prompt boundary: selected-skill system prompts and auto-skill-routing
  catalogs now render skill metadata as sanitized JSON objects instead of raw interpolated prose,
  collapse control-character / multiline free-text fields, and explicitly tell the model to treat
  skill ids, names, descriptions, and source fields as inert data rather than executable
  instructions. This closes the prompt-injection gap where a malicious `SKILL.md` preview or
  unusual filesystem-derived skill name could steer routing or chat behavior before `load_skill`
  was even called.
- Added a dedicated `npm run -s test:smoke:memory` suite so the highest-value memory-path checks
  can be rerun in one command: it covers settings-side embedding selection, runtime embedding
  resolution, long-memory CRUD/search behavior, multilingual retrieval, degraded fallback, and the
  chat / IPC / daemon / reflection integration paths that consume memory.
- Added explicit embedding-model selection under `Settings -> Memory`: memory retrieval can now be
  pinned to a specific provider/model pair instead of always auto-detecting, while still falling
  back safely to auto detection or local hash search when the configured embedding runtime becomes
  unavailable.
- Tightened automatic long-memory retrieval relevance with a dedicated planner step: before chat
  memory search runs, iKi now asks the tool model whether retrieval is worthwhile for the latest
  user turn and rewrites relevant queries toward durable preferences / project constraints instead
  of embedding the raw sentence verbatim. Planner failures fall back to the raw query so memory
  remains available even when the rewrite layer is unavailable.
- Fixed chat reference-summary consistency for the thread-scoped execution `todo` planner:
  transcript-hidden planner calls no longer inflate the assistant's visible `N tools` badge, so
  the summary now matches the tool cards users can actually inspect in the message body while
  `load_skill` continues to be reported under skills instead of tools.
- Replaced the old ASCII-only hashed long-memory retrieval path with a real embedding pipeline:
  long-memory writes now prefer provider-backed `/embeddings` requests (OpenAI first, then other
  OpenAI-compatible providers that advertise embedding models), embedding provenance is stored in
  `memory_long.metadata`, searches lazily backfill legacy rows to the active embedding fingerprint,
  and runtime failures degrade to the local hash embedding path instead of silently breaking memory
  lookup. This fixes the worst multilingual retrieval gap, including Chinese memory recall.
- Fixed daemon/app-client auto-tool parity so newly registered external clients no longer default to
  a hard-coded `web`/`fetch` allowlist. Client defaults now expand to the current auto-capable
  built-in tool set, explicit empty tool/MCP arrays now truly disable those surfaces instead of
  silently falling back to defaults, and MCP server-scoped permissions now also authorize explicit
  MCP tool names. This closes the gap where auto-mode prompt apps or external chat clients could
  appear "tool-starved" even though the desktop chat path already exposed a much broader tool
  surface under the same approval model.
- Fixed Chat UI draft model persistence so `Select model` now remembers the last explicit
  provider/model choice across renderer reloads and app restarts instead of falling back to the
  first enabled model every time. The renderer now stores draft composer selection in app config
  and restores it only when no thread is active, so per-thread model routing still takes
  precedence once a conversation is selected.
- Tightened temporary thread-workspace UX and invariants in the composer: the workspace trigger now
  marks thread-scoped temporary workspaces with a `T` badge, locked thread workspaces expose a
  richer hover tip with the scratch-path and rebinding rule, first-turn sends proactively refresh
  any missing workspace binding before streaming so the renderer stays aligned with the persisted
  thread record, and threads with existing messages no longer allow workspace rebinding in either
  the UI or the persistence layer.
- Re-opened the shell tool to auto routing under the explicit workspace + approval boundary: auto
  mode can now let the model choose shell when live local inspection is materially necessary, tool
  routing / tool-runner prompts now explicitly prefer verification over guessing for current local
  or web state, and tool-free turns carry a no-tools capability prompt so the assistant no longer
  claims it can run local commands when this turn has no tools.
- Added declarative skill-level required built-in tools via `SKILL.md` frontmatter
  (`required_tools` / `requiredTools`) and merge those requirements into the same chat turn before
  tool registration, so skills that depend on built-in capabilities such as `shell` can enter the
  existing approval flow without needing a second model round or prompt-time heuristics.
- Added first-class per-model options to provider settings instead of treating every selected model
  as an untyped string: provider configs can now persist model-level capability metadata
  (`tool calling`, `reasoning`, `vision`, `structured outputs`, token limits, display name) plus
  advanced provider-specific AI SDK call options as JSON, and the runtime now actually reads those
  settings when constructing model calls.
  This closes the previous gap where manually added gateway models such as custom `gpt-5.4`
  entries had no place to declare their capabilities or pass through provider-specific options,
  so they could look configured in Settings while still running with a degraded default model
  contract. Existing databases are upgraded in place through a new SQLite migration that adds the
  provider `model_options` column without breaking older provider records.
- Tightened those per-model call settings again for OpenAI-backed reasoning models: shared runtime
  call assembly now suppresses unsupported `temperature` parameters for GPT-5 / reasoning-style
  Responses calls, including custom gateway models, while still preserving the explicit
  `reasoningEffort: "none"` escape hatch on compatible GPT-5.1 / GPT-5.2 models. This removes the
  repeated AI SDK warning path where a model could be configured correctly for reasoning yet still
  receive an invalid sampling parameter from generic runtime defaults.
- Fixed thread-level model routing so chat execution now honors the exact selected provider
  instance, not just its shared provider type: when multiple enabled configs use the same runtime
  type, switching providers no longer silently falls back to the wrong backend or leave later sends
  stuck against a stale selection.
- Hardened auto-generated thread titles against transcript leakage: title generation now prefers
  user-authored content over assistant/tool narration, and the title runtime treats transcript text
  as inert data instead of executable instructions, so tool-returned timestamps no longer become the
  conversation title by accident.
- Fixed provider-icon consistency in `Select model`: custom providers there now use the same
  custom-provider icon resolution as `Settings -> Provider`, so gateways on custom types like
  `openai-compatible` no longer render as built-in vendor icons or fall through to a broken
  `custom.svg` lookup.
- Provider configuration changes now broadcast across renderer windows instead of staying local to
  the settings form that saved them: after add/update/delete, the chat composer and settings
  model-dependent selectors reload their provider lists immediately, so newly added providers show
  up in `Select model` without needing to reopen the window.
- Added first-class personal-skill management tools: iKi can now list, read, create, update, and
  delete user-managed `SKILL.md` files under the Personal skills root directly, instead of only
  discovering them passively or relying on workspace tricks. Because this is self-modification,
  skill writes and deletes now use a locked approval mode that is not downgraded by global
  tool auto-approve.
- Continued the AI SDK boundary cleanup through the chat UI transport itself: assistant reference
  metadata now uses canonical AI SDK `data-*` UI parts (`data-skill-usage`,
  `data-memory-retrieval`, `data-context-report`, `data-affect-signal`), shared chat codecs now
  normalize older flat parts into that representation on load/persist, and main/renderer chat
  flow now shares typed `ChatUiMessage` / `ChatUiMessageChunk` aliases instead of carrying a
  parallel ad-hoc part protocol.
- Tightened that chat metadata boundary again: legacy flat reference parts are now normalized in
  one shared message-part ingress instead of being re-detected independently in persistence
  sanitization, codec parsing, and AI SDK model-message conversion.
- Added a startup SQLite migration that rewrites historical `chat_messages.message` payloads into
  canonical AI SDK storage form, so old flat metadata parts and `content`-only rows are cleaned
  once instead of being carried forever behind read-time compatibility branches.
- Tightened the shared runtime helper surface around that storage cleanup: renderer/chat code and
  its tests now treat only canonical `data-*` metadata parts as valid runtime shapes, while the
  old flat form remains accepted only in explicit boundary normalization code.
- Removed the remaining source-level `as unknown as` boundary patches: the Anthropic model factory
  now validates adapter return shape explicitly, the NapCat bridge now builds typed transport
  messages directly instead of recasting mixed payload arrays, IPC fallback cloning now handles
  numeric and bigint typed arrays without unsafe coercion, and config-schema fallback defaults now
  materialize schema-valid theme/default records instead of relying on double assertions.
- Tightened the AI SDK/tool-schema boundary again: tool registration now builds typed AI SDK

  longer uses raw `event.sender as ...` assertions, and tool JSON Schema derivation now goes
  through a shared Zod v4-native adapter so `load_skill` and other tool contracts no longer depend
  on the stale `zod-to-json-schema` v3 bridge.
- Reduced repeated infrastructure seams across shared/main/renderer: timestamped runtime IDs now
  come from a shared helper, several JSON round-trip clone sites now reuse a shared plain-data
  clone utility backed by the IPC serializer, and renderer components with mandatory preload access
  now enter through one typed `electronAPI` helper instead of scattered local assertions.
- Continued shrinking repeated low-level helpers: identical ISO timestamp and whitespace
  normalization logic now lives in shared utilities instead of being copy-pasted across DB,
  task-scheduling, relationship, chat-context, and renderer reference modules.
- Clarified custom-provider protocol expectations in Settings: the add-custom-provider modal now

  `openai-compatible` Chat Completions, OpenAI `Responses`, and `anthropic-compatible`
  `Messages`, and persists that API-format choice onto the runtime model factory so custom
