# 成功终态与旧动作重复执行

2026-10-04。基线 f407caf；影响为当前输出提交路径，以及尚未接入生产的 Pi 审批候选协议。

SQLite 拒绝文字事件时，旧修复虽然挡住 UI 发布，却保留一个局部缓冲后返回成功。公开 stream 返回了回答 text，但聊天行和日志重建没有回答。提交确认与 turn 终结必须属于同一执行契约；空显示与空日志满足子集断言，不能证明任务成功完成。

另一个反例是已批准、已消费的旧动作有成功结果，新候选私有执行表为空。候选协议把空表当成未执行，工具被调用第二次。批准、消费、执行开始与执行完成是不同事实；新记录缺失不是旧效果不存在的证据。

修正：提交失败终结 turn，沿现有 run working 保存生成文本；已发生事实原子追加，条件动作使用 revision CAS。动作绑定和真实结果写入 Session log，复用原历史 converter 导入旧结果；旧 consumed 无结果拒绝执行。删除测试私有执行表，当前进程的重复调用复用 live promise，跨进程通过同一日志 claim。

边界回归先在旧代码失败：公开 stream 的失败终态、已完成旧动作不重复执行。进一步验证结果提交失败不重做效果、取消前零执行、删除旧投影后的纯结果恢复、原工作区真实文件写入，以及两个独立进程只产生一个效果。运行结果随交付报告记录。完整 Pi 执行循环切换仍是后续工作。
